# Аудит безопасности: Fanvue Market Telegram Mini App

## Вердикт: Скрытых бэкдоров и вредоносного кода НЕ обнаружено

Проверены все серверные роуты, блокчейн-модули, клиентский стор и утилиты. Разработчик **НЕ внедрял** скрытых функций, бэкдоров или механизмов кражи средств. Нет `eval()`, динамических `Function()`, скрытых `fetch()` на неизвестные домены, подмены кошельков.

Однако есть **реальные архитектурные уязвимости**, которые могут быть использованы.

## КРИТИЧЕСКИЕ (Безопасность, Деньги)

### C1. `/api/notify` — любой пользователь может отправлять сообщения от имени бота
**Файл:** `server/routes/notify.ts`
Любой аутентифицированный пользователь может POST на `/api/notify` с произвольным `chatId` и текстом. Бот отправит сообщение кому угодно — фишинг, спам, социальная инженерия.
**Исправление:** Ограничить `chatId` только для админов.

### C2. `VITE_ADMIN_IDS` — plaintext UID админа в клиентском бандле
**Файл:** `src/fanvue/config.ts`
Если `VITE_ADMIN_IDS` задан, реальный Telegram UID админа попадает в JS-бандл в открытом виде. Любой может извлечь его из исходников.
**Исправление:** Удалить `VITE_ADMIN_IDS` полностью, использовать только хеши (`VITE_ADMIN_HASHES`).

### C3. Сопоставление платежей только по сумме — без проверки отправителя
**Файл:** `server/blockchain/matcher.ts`
Матчер берёт первый pending ордер с подходящей суммой. Если два юзера создали ордера на близкие суммы одновременно — платёж User A может зачислиться User B.
**Исправление:** При множественном совпадении — помечать для ручной проверки.

### C4. Нет серверного rate-limiting
Express сервер не имеет ограничений на частоту запросов. Все эндпоинты можно спамить:
- `POST /api/order` — бесконечное создание ордеров
- `POST /api/notify` — бесконечная отправка сообщений
**Исправление:** Добавить `express-rate-limit`.

## ВЫСОКИЕ (Ломают функционал)

### H1. Статус ордера доступен без авторизации
**Файл:** `server/routes/orders.ts`
`GET /api/order/:id` — нет проверки `verifyInitData`. Любой, кто угадает ID ордера, увидит его детали (сумма, сеть, tx_hash).

### H2. Реферальный баланс — полностью клиентский
Весь реферальный механизм (`ref_balance`, `ref_earned`, `spendRefBalance`) работает в localStorage. Пользователь может подменить данные и запросить вывод фейкового баланса.

### H3. `creditDeposit` может быть вызван на клиенте без сервера
Если `VITE_API_URL` не задан — депозит зачисляется чисто на клиенте. В проде это может произойти при ошибке конфигурации.

### H4. Bitcoin — зачисление без подтверждений
**Файл:** `server/blockchain/bitcoin.ts`
BTC-транзакции зачисляются сразу, без ожидания подтверждений. Риск double-spend атаки.

## СРЕДНИЕ

### M1. Webhook secret опционален
Если `TELEGRAM_WEBHOOK_SECRET` не задан — любой может отправлять запросы на `/api/telegram/webhook`.

### M2. Утечка памяти в `usedAmounts`
`Set<number>` в `server/routes/orders.ts` растёт бесконечно при высокой нагрузке.

### M3. Фейковые продажи на главной
`salesGen.ts` генерирует детерминистические фейковые продажи. Не уязвимость, но вводит в заблуждение.

### M4. Нет CORS на Express
Без Caddy любой origin может делать API-запросы.

### M5. localStorage хранит переписку поддержки
`supportMessages` (включая возможные вложения) сохраняются в localStorage. На общем устройстве — доступны.

### M6. Нет проверки подтверждений BTC
Транзакции матчатся мгновенно, без ожидания confirmations.

## НИЗКИЕ (Качество кода)

### L1. Мёртвые API-эндпоинты на клиенте
Клиент вызывает `/api/support/messages`, `/api/support/message` и множество admin-эндпоинтов — но на сервере их нет. Вызовы молча возвращают `null`.

### L2. `isValidAmount` отклоняет >3 знаков после запятой
Валидные крипто-суммы с 4+ знаками будут отклонены.

### L3. Мусорные зависимости TanStack Router
`@tanstack/react-router` и `@tanstack/react-start` в `package.json`, но приложение использует `react-router-dom`. Мёртвый код увеличивает бандл.

### L4. Mock-данные в проде
`AdminUsers.tsx` содержит `MOCK_USERS`, `store/index.ts` содержит `MOCK_LOGS` — показываются в админке рядом с реальными данными.

### L5. Нет валидации длины строк на сервере
Можно отправить огромные строки в `kind`, `network` — потенциальный раздув SQLite.
